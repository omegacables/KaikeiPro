# lessons

ユーザーから訂正を受けたときに、同じ間違いを繰り返さないための記録。

## UI

### はみ出しを「隠す」で解決しない
`overflow-x-hidden` で横スクロールを止めたところ、画面を狭めたときに
操作ボタンが見えず押せなくなった。スクロールできる方がまだましで、
内容を隠すのは常に悪手。はみ出しは**原因側**（折り返さない見出し行、
縮小を禁止する shrink-0、表の min-w）で断つ。

### 見出し行には折り返しを入れる
`flex justify-between` だけの見出し行は、画面を狭めると操作ボタンが
はみ出す。`flex-wrap` と `gap` を必ず付け、ボタン群にも `shrink-0` を
付けない。15画面で同じ不具合が出ていた。

### 幅・色は目測でなく数値で決める
「見づらい」の指摘に対し、ダークテーマの背景とカードの明度差が
1.15:1 しかないことを計算で確認してから直した。感覚で色を変えると
「なんとなく変えた」で終わる。コントラスト比を出してから選ぶ。

### 同じものを2つの名前で呼ばない
同じ画面をサイドバーは「顧客管理」、ヘッダーは「顧問先管理」と
表示していた。ユーザーは別機能だと受け取る。用語は一覧で洗って統一する。

### 説明文はUIの構造で解決してから足す
「同じ欄が2つある」と言われて説明文を足したが、枠を分けたら不要になった。
文字で補う前に、配置・色・枠で区別できないか考える。

## 実装

### 数値の丸めは「もっともらしい別の値」を生む
日付入力で範囲外の月を12月に丸めていたため、`2030` が 2026-12-30 という
実在しそうな日付に化けた。打ち間違いに気づけない。**解釈できない入力は
受け付けず、元の値を保つ**。丸めてよいのは意味が変わらない範囲だけ
（2月31日 → 2月28日）。

### 集計は「区分」ではなく「意味」で数える
支払利息を entry_type='interest' だけで数えていたため、元金と同時に払う
銀行返済の利息が漏れ、内訳明細書の支払利子額が常に0になっていた。
何を数えるべきかを会計の意味から決める。

### 期間の起点を「今日」にしない
認定利息の試算を「今日から決算日まで」で数え、経過期間が抜けて
金額が6割程度に過小に出ていた。税額を少なく見せる誤差は特に危険。
発生日または期首を起点にする。

### 失敗したときに入力内容を消さない
AI下書きの登録に失敗しても下書きを全消ししていたため、直して
やり直せず、AIを呼び直す（＝費用がかかる）しかなかった。
失敗した分は残す。

### 連打は state では止まらない
二重登録が起きた。`setBusy` の反映は非同期なので、連打には ref で
即座に蓋をする。あわせて「登録できた」ことが分かる表示を出す
（何も起きないと、もう一度押したくなる）。

### 名前の一致に頼った突き合わせは失敗する
通帳の「アンドウ レン」と台帳の「代表取締役 ○○」は一致しない。
一致を前提にすると1件も登録できない。**その場で選び直せる手段**を必ず置く。

## 進め方

### 遅い・ずれるは実測してから直す
「遅い」の指摘に対し、devサーバーのログで往復回数と各所要時間を出してから
直した。「ずれる」は推測で2回外し、全体のスクリーンショットで原因が判明した。
症状が曖昧なときは、数値か全体像を先に取る。

### 他社の作りを調べてから設計を決める
役員送金の判別を独立した入力欄に作ったが、freee・マネーフォワード・弥生は
いずれも「一覧に並べてその場で直す」形だった。業界の標準操作から外れると
使いにくい。競合の実装を調べてから決める。

### 画面確認は省略できない
テスト・型チェック・ビルド・DB検証がすべて通った状態でも、実際に触ると
会計上の重大な不具合が2件見つかった（利息が借入金残高を増やす、
支払利子額が常に0）。「利息計 ¥0」という小さな表示のずれが入口だった。

### 入力を黙って元に戻してはいけない
日付欄は、読み取れない打ち込みを blur で元の値に戻していた。「中途半端な表示を
残さない」つもりの配慮が、**打った日付が消えて初期値（今日）のまま登録される**
事故になり、利用者は気づけなかった。会計データでは、入力の取りこぼしを
黙って埋めるより、赤枠を残して止める方が安全。

### 入力欄の不具合は「2回目のクリック」を試す
1回目のクリックは onFocus の全選択が効くため正常に動く。不具合は
**2回目以降のクリック（全選択が外れた状態）** でしか出なかった。
入力欄を確認するときは、クリック2回・貼り付け・日本語入力ONの3つを必ず試す。

### 自動操作ツールの入力を鵜呑みにしない
ブラウザ自動操作の `key: "Return"` は `e.key` が空文字になり、Enterが
効かないという**存在しない不具合**を再現してしまった。`"Enter"` では正常。
同様に `type` は keydown を発火しないため、keydown に頼った対策は検証できない。
再現したら、まずツール側の挙動（イベントの中身）を確認する。

### 既存ファイルを読まずに上書きしない
`amount-input.test.ts` を新規のつもりで `cat >` し、既にあったテスト17件を
消していた。全体のテスト数が想定と合わないことに気づいて git から復元したが、
気づかなければテストごと消えていた。**書き込む前に、対象が既にあるかを見る。**
